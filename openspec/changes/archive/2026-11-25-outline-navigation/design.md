# Design

## Context

参见 `proposal.md`。当前实现的关键约束：

- 大纲链接只带 `data-toc-id`，指向渲染后的标题元素；源码视图是 Chroma 生成的 `<pre class="chroma source-code">`，没有标题锚点，也没有标题到源码行的映射。
- `updateActiveTOC()` 用窗口坐标判断当前标题（`getBoundingClientRect().top <= 130`），并且在源码模式下直接返回。双视图的阅读区从 60px 顶栏下方开始，浏览器按 `scroll-margin-top: 80px` 定位后标题在窗口中的 top 约为 140px，超过 130 的阈值，所以高亮停在上一节。
- 双视图下滚动阅读区会同步源码区并按比例回写；源码区滚动时同步阅读区，但阅读区的滚动事件被标记为“程序同步”而跳过 `updateActiveTOC()`，因此滚动源码区时大纲不更新。
- 源码模式的大纲点击处理器会调用 `applyMode("render", true)`，这是既有 `source-view` 要求的行为，本变更将其移除。
- 源码视图显示包含 front matter 的原始文件；渲染解析前会去掉 BOM 和 front matter。标题行号必须按原始文件计算，否则有 front matter 时源码定位会偏移。

## Goals / Non-Goals

**Goals:**

- 点击大纲后，阅读区、双视图源码区、源码模式都定位到同一个标题，大纲高亮与点击项一致。
- 双视图和源码模式下的滚动都能驱动大纲高亮，且高亮判定以实际滚动区域的顶部为基准。
- 源码定位对自动换行、front matter、BOM 都成立。

**Non-Goals:**

- 不改文件树、跨文档导航、深度链接的文档切换逻辑。
- 不引入滚动动画或平滑滚动。
- 不重写源码高亮或大纲生成逻辑，只补充行号元数据。
- 不要求源码区和阅读区在自由滚动时逐行严格对齐；自由滚动仍沿用现有比例同步。

## Decisions

### 1. 标题记录原始源码行号

在 `Heading` 上增加 0 起算的 `Line` 字段，渲染大纲时输出 `data-toc-line`。行号按**原始文件**计算：先记录 BOM 和 front matter 被移除的前缀长度，再用“前缀 + goldmark 标题起始偏移”之前出现的换行数得到行号。替代方案是让前端按标题文本搜索源码，但标题重复或出现在代码块中时不可靠，因此否掉。

### 2. 前端用 DOM Range 把行号换算成像素位置

源码视图不按固定行高排版，长行会换行，不能简单用“行号 × 行高”。实现上遍历 `<pre>` 的文本节点，找到目标行起始字符，在该位置创建一个单字符 Range，读取其 `getBoundingClientRect()`，再换算成相对滚动容器的 `scrollTop`。结果按“文档 section + 容器宽度”缓存，窗口尺寸变化或切换文档时失效。替代方案是给每行包一层 span，但需要改动 Chroma 输出，收益不足。

### 3. 大纲点击统一由一个函数处理

拦截大纲链接的默认跳转，按当前模式执行：

- 阅读模式：滚动窗口到标题（保持现有 72px 顶部偏移）。
- 双视图：滚动阅读区到标题，再把源码区滚动到同一标题的源码行；两边都定位后再更新高亮。
- 源码模式：不再调用 `applyMode("render")`，直接滚动窗口到源码中该标题的行位置。

定位完成后显式把被点击的大纲项设为 active，避免滚动事件尚未派发时短暂高亮错误。不写入 `#标题` 哈希，保持现有“点击大纲后不保留锚点哈希”的行为。

### 4. 高亮判定以滚动容器顶部为原点

`updateActiveTOC()` 在阅读模式和源码模式下以窗口为原点；双视图下以当前 `.doc-rendered` 或 `.source-view` 的 `getBoundingClientRect().top` 为原点。阈值沿用 130px，使标题进入容器顶部附近即成为当前项。源码侧用第 2 条的行位置换算，不依赖渲染标题的几何位置。

### 5. 双视图下滚动哪一侧就按哪一侧更新高亮

阅读区滚动时继续同步源码区比例并更新高亮；源码区滚动时同步阅读区比例，但高亮改为按源码行位置计算，而不是跳过更新。程序触发的同步滚动仍通过 `pendingSyncs` 抑制回环，但不再抑制高亮更新。

### 6. 源码不可用时安全降级

文档没有源码（`HasSource` 为 false）时，源码区没有可定位的 `<pre>`。此时双视图只定位阅读区，源码模式保持当前位置并只更新高亮到可计算的范围，不抛错、不强制切换模式。

## Risks / Trade-offs

- **Range 测量成本** → 按 section 和宽度缓存行位置，只在滚动时比较缓存的数值；尺寸变化清空缓存。
- **front matter / BOM 行号偏移** → 行号基于原始文件前缀计算，并用含 front matter 的测试覆盖。
- **自由滚动时比例同步与标题对齐不一致** → 点击大纲时按行精确对齐；自由滚动仍用比例，这是现有行为的保留，不扩大范围。
- **滚动事件回环** → 保留 `pendingSyncs` 抑制程序同步触发的事件，但把高亮更新放在同步逻辑之前/独立执行，避免再次漏更新。

## Migration Plan

模板和共享 JS 变化后提升 `cacheGeneration`，旧渲染页面会在下次打开时重新生成。无需数据迁移或回滚步骤；回滚时恢复旧模板和脚本并再次提升缓存代次即可。
