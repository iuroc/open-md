# Design

## Context

现有目录模式由 `scan.Directory` 调用 `os.ReadDir` 读取一层，随后 `buildDirPage` 把所有文档预渲染进同一个 `index.html`，侧栏用平铺的 `doc-items` 模板展示。渲染、锚点、脚注和跨文档链接都基于“所有文档已在同一页”这一前提。

约束：

- Windows、Go 1.26，单 exe，无 HTTP 服务、无多页面输出。
- 目录模式上限仍为 500 篇、合计 25 MiB、单文件 32 MiB。
- 文件树必须和当前“点击文档即切换 section”的模型兼容。
- OpenSpec 目录的标题高度重复，文件树不能以 H1 作为主标签。

## Goals / Non-Goals

**Goals:**

- 递归发现嵌套 Markdown，并在打开扫描根时正常工作。
- 用文件树替代平铺列表，支持展开、折叠、选中和链接定位。
- 在没有 Markdown 的根目录、深层目录、同名文件和大量归档下保持确定性。
- 不跟随符号链接/junction，不进入已知重目录。

**Non-Goals:**

- 不做多页面导出、懒加载或按需启动服务。
- 不做文件监听、重命名、编辑或删除。
- 不做文件系统级搜索；首版不增加过滤输入框。
- 不特殊识别 OpenSpec 目录结构，保持通用文件树。

## Decisions

### 递归遍历放在 `internal/scan`

使用自定义深度优先遍历，而不是 `filepath.WalkDir`：

- 需要在进入目录前判断重解析点，避免 junction 循环；
- 需要统一控制最大深度、访问条目预算和自然排序；
- 需要在跳过重目录时不产生噪音警告。

`Document` 增加 `RelPath`（相对扫描根，统一 `/` 分隔），保留 `Name` 作为 base name 兼容现有测试和警告。扫描结果先收集候选，再按“深度从浅到深、同深度自然路径序”选择前 500 篇，保证截断确定性。

备选：直接 `filepath.WalkDir`。实现更短，但 junction/深度/预算和跳过目录的控制点不足，容易在项目根目录这类输入上失控。

### 重解析点与忽略目录

- 跳过符号链接、junction 和带 `FILE_ATTRIBUTE_REPARSE_POINT` 的目录项。
- 忽略 `.git`、`.svn`、`.hg`、`node_modules`、`vendor`、`.obsidian`、`.trash`、`$RECYCLE.BIN`、`System Volume Information`。
- 子目录读取失败只记警告并继续，符合现有“单个异常不破坏整篇文档”的原则。

备选：只在 `WalkDir` 回调里判断 `IsDir`。无法可靠阻止 Windows junction 循环。

### 文件树在服务端构建，前端只负责展开状态

`render` 包新增树节点结构，从扫描结果的相对路径构建树，模板递归渲染。这样：

- 树结构与文档 ID 的对应关系可单元测试；
- 前端不需要解析路径或重新排序；
- 初始展开状态由服务端标记，JS 只处理点击、链接跳转和滚动定位。

备选：前端从文档列表构建树。会让排序、同名文件和测试分散到 JS，且容易出现首屏闪烁。

### 树节点标签使用 basename

文件节点显示 `proposal.md`、`design.md`、`spec.md` 等文件名；`title` 属性提供“文档标题 — 相对路径”。目录节点显示目录名，`title` 提供相对路径。

备选：用 H1 作为主标签。OpenSpec 下 `# Proposal`、`# Design`、`# Tasks`、`# Spec Delta` 大量重复，会让树失去辨识度。

### 初始文档与展开状态

- 根层存在 `README.md` / `index.md`（大小写不敏感，兼容 `.markdown`）时选它；
- 否则选选择顺序中的第一篇（最浅层、自然序）。
- 服务端只展开当前文档的祖先目录，其余折叠。
- 前端 `revealDoc(docID)` 在切换文档后展开祖先、滚动到节点并高亮。

### 树外链接文档单独分组

扫描根之外的链接文档继续由 `collectLinkedMDSources` 预渲染，但在侧栏归入“链接文档”分组，不插入真实文件树。树只反映磁盘上的扫描结果，避免路径伪造和重复节点。

### 上限与预算

新增预算：最大深度 12、最多访问 20,000 个目录项。现有 500 篇 / 25 MiB / 32 MiB 不变。达到任一限制时保留已加载文档并显示对应警告；截断顺序由“深度 + 自然路径”决定，保证重复扫描结果一致。

备选：不设访问预算。右键驱动器根目录或超大工作区时可能长时间遍历且无反馈。

## Risks / Trade-offs

- [深层目录使侧栏缩进过深] → 使用紧凑缩进、标签省略和悬停完整路径；侧栏本身可收起。
- [归档增长后接近 500 篇上限] → 浅层优先截断，先保留 `specs/`、活动 change 和根文档；明确提示已截断。
- [Windows junction 检测依赖平台 API] → 封装平台辅助函数，非 Windows 退化为 `ModeSymlink` 检查，并在测试中覆盖 junction 或跳过不支持的环境。
- [树节点较多时 DOM 体积增加] → 只加载到现有 500 篇上限；树节点不重复渲染正文，额外开销远小于正文。
- [文件树改变现有侧栏行为] → 保留“文件列表 / 大纲”两个 Tab 和现有关闭/全宽交互；更新 README 和验收清单。

## Migration Plan

1. 先实现扫描递归和相对路径，保持平铺列表可用，运行现有测试。
2. 再引入树结构和模板，替换目录模式的 `doc-items` 渲染。
3. 最后补前端展开/定位、README 和验收文档。
4. 回滚方式：恢复 `scan.Directory` 的单层实现和原 `doc-items` 模板即可；无数据迁移、无外部依赖。
