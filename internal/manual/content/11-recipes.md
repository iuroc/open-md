# 第 11 章：五个实战配方

前面的语法单独看都简单，真正写文档时需要组合使用。这一章给出五个可以直接套用的模板。

## 你会学到

- 项目 README、学习笔记、接口说明、会议记录和长文的常见结构。
- 每种场景该用哪些 Markdown 元素。
- 怎么让文档在阅读和打印时都清楚。

## 基本写法

### 1. 项目 README

```markdown
# 项目名

一句话说明项目解决什么问题。

## 快速开始

1. 下载
2. 安装
3. 打开示例

## 功能

- 功能一
- 功能二

## 许可证

MIT
```

### 2. 学习笔记

```markdown
# 主题

## 结论

- 要点一
- 要点二

## 推导

正文、公式说明和代码。

## 待办

- [ ] 补充例子
- [x] 整理关键词
```

### 3. 接口说明

接口文档通常由标题、参数表和响应示例组成。参数表可以直接写成真实表格：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| page | 否 | 页码 |

响应示例放在带 `json` 标记的代码块里：

```json
{"items": []}
```

### 4. 会议记录

```markdown
# 2026-11-25 周会

## 结论

- 决定一
- 决定二

## 待办

- [ ] 张三：整理方案
- [ ] 李四：补充数据
```

### 5. 长文打印

长文用清晰的标题层级组织，每节不要太长；代码块和宽表格交给打印样式处理。按 `Ctrl + P` 时，OpenMD 会自动使用白底、让代码换行并适配表格宽度。

## 在 OpenMD 里怎么看

用双视图对照模板和效果，确认标题层级、列表缩进和表格列数。长文可以先用大纲跳转检查结构，再打印预览确认分页和表格没有被裁切。

## 常见错误

- 模板里塞太多内容：先写骨架，再逐节补充。
- README 太长：详细说明放到 `docs/`，入口只保留导航。
- 接口文档缺少示例：读者无法判断返回结构。
- 会议记录没有负责人和状态：待办无法跟进。
- 长文没有小节标题：大纲为空，阅读和打印都难定位。
